## 背景
当前已有原子任务与任务池初版实现，目标是覆盖大部分 AT 指令同步流程。运行环境需要同时兼容裸机与 RTOS，并且软件中禁止动态内存分配与驼峰命名。

## 目标 / 非目标
- 目标
  - 支持多个任务池实例顺序执行，同一时刻仅一个活跃池
  - 提供可替换的同步机制抽象接口，便于裸机与 RTOS 适配
  - 全部任务池与任务状态使用静态内存
  - 保持同步 AT 指令流程
  - 新增接口与结构体统一下划线命名
- 非目标
  - 异步或多段反馈的 AT 流程
  - 动态扩容或动态注册任务
  - 完整的 RTOS 适配实现

## 决策
- 采用“任务池实例 + 原子任务状态机”的分层结构，每个池实例独立维护状态与任务序列
- 同一时刻仅允许一个任务池处于执行态，切换由上层显式触发
- 任务池实例数量与容量通过编译期常量或配置宏固定
- 同步机制通过函数指针或回调表抽象，裸机可用空实现或轮询替代
- 允许对结构体内容重划分，但保留现有 API 的兼容入口
- 保持现有任务执行核心逻辑不变，只调整结构与扩展能力
- Usr 目录划分为 include/src/test，测试接口与可移植接口独立
- 测试程序作为单独入口，便于调试任务池流程
- 采用严格 TDD 流程推进变更
- TDD 用例骨架放在 Usr/test，并通过测试入口统一触发

## 考虑的替代方案
- 动态链表队列：不符合禁止动态内存的约束
- 每个任务单独线程：在裸机不可行，且资源开销过大

## 风险 / 权衡
- 静态容量过小导致任务溢出 → 增加容量配置与边界处理策略
- 多池顺序执行可能带来切换时延 → 通过上层调度时机控制

## 迁移计划
- 将现有全局任务池状态封装为单个任务池实例
- 抽离同步接口并提供默认空实现
- 保留现有 API 外观，内部转发到新的结构体布局与实现
- 迁移现有文件到 include/src/test 并更新包含路径

## 开放问题
- 任务池实例的默认数量与容量配置值
- 同步接口的最小函数集合与返回码约定
- 任务池切换接口的最小输入与返回码约定
- 任务异常处理需要包含的最小信息

## TDD 流程

本变更采用严格测试驱动开发（TDD）流程，确保代码质量与功能正确性。

### TDD 循环

1. **红（失败）** - 编写测试用例，验证其失败
   - 在 `Usr/test/task_test_api.c` 中添加测试函数
   - 编译运行，确认测试失败（红色）

2. **绿（通过）** - 编写最小实现使测试通过
   - 在 `Usr/src/` 中实现功能代码
   - 仅编写足以让测试通过的代码
   - 编译运行，确认测试通过（绿色）

3. **重构** - 优化代码结构
   - 消除重复，提取抽象
   - 保持测试通过状态

### 测试组织

```
Usr/test/
├── task_test_api.h    # 测试接口声明
├── task_test_api.c    # 测试场景实现
└── task_test_main.c   # 测试入口
```

### 测试场景

- **场景 1**：多任务池顺序执行
  - 创建池 1，添加任务，执行完成
  - 创建池 2，切换激活，执行完成

- **场景 2**：兼容接口验证
  - 使用原有 `set_task_pool()` / `task_pool_fsm()` 接口
  - 验证行为一致性
